PS2 Servers

Serve your games and files to network-capable PS2 homebrew. Desktop has six server cards in a small GUI; Core runs the same servers from a terminal; Edge runs on routers, NAS and headless computers. Choose a protocol your loader supports, select your folder or image, and start the server.

Choose the server your loader supports.

The Desktop launcher shows setup values for each mode. Loader support varies: a server cannot add UDPFS, HTTP, or a newer SMB dialect to a client that does not implement it.

SMBv1

Dialect, port, and authentication guide

Guest file sharing for OPL and other SMBv1 clients. Implements SMB itself without enabling Windows SMB1. Default custom-port operation leaves Windows File Sharing running; optional Take port 445 temporarily stops it.

Desktop: port 1025 · share games

UDPFS

Serves a folder and/or a disk image over UDP — the newer protocol. Optionally decompresses CHD/CSO/ZSO images on the fly so they load as plain .iso.

UDPFS-capable loader required

UDPBD

Serves one disk image as a UDP block device. Requires a UDPBD-capable loader and compatible PS2 network settings; the server is discovered by broadcast.

UDP 48573 · disk image

SMB2 / SMB3

Two Desktop cards for authenticated sharing with clients supporting SMB2 or SMB3 (up to 3.0.2). Use SMBv1 for an SMBv1-only loader. Both default to TCP 1445, so use different ports to run both.

HTTP games · experimental

Generated game list and HTTP Range streaming for compatible OPL HTTP clients. Read-only, with server-side CHD/CSO decoding and client-side ZSO. Host-tested; console validation remains separate.

Edge & Web GUI

Native Go UDPFS, SMBv1 and UDPBD server. Its optional web dashboard manages Edge services; it is separate from HTTP game serving. LAN dashboard access requires a password and service management requires the appropriate host setup.

Read the running server’s output for its actual address and port. Use a PS2 that boots compatible homebrew with network settings matching the PC. A menu listing is not yet proof of successful game launch.

UDPFS settings worth knowing.

Start with Protocol mode Auto. If games list but fail at launch, check the PC address used for replies before changing compatibility or timing.

Bind address (PC)

Select the PC IP connected to the PS2 in the LAN IP box, then click Use LAN IP on the UDPFS card. You can also type that address. Stop and start UDPFS to apply it.

Use the PC’s address, not the PS2’s. Blank restores automatic binding. The button saves a copy; a later LAN IP change does not update that copy. Core binds its data socket while discovery stays on all interfaces.

--bind 192.168.0.3 · example PC address

Auto and Modulo

Auto negotiates Standard and Modulo independently for each peer. Leave Enforce Modulo mode unticked for normal Auto operation. That override selects Core’s legacy single-port Modulo behavior.

Protocol and Core/Edge differences

Idle timeout

UDPFS drops a console once it goes quiet, closing whatever files it had open. There's no disconnect packet in the protocol — a paused game and an unplugged console look identical on the wire — so the timeout is the only thing that tells them apart.

Default 1 hour, adjustable 60s–24h under Advanced. Zero is rejected by Core; it does not disable expiry. Lower it only to clear stale consoles faster; too low and a long pause loses its game.

--peer-timeout SECONDS

Ports

Leave them alone unless something needs them predictable. Discovery is 0xF5F6; the server also opens an automatic data port at startup. Pin Data port when a manual firewall needs a predictable pair, and allow both ports.

Single-port mode serves both on one port for networks that can't handle the two-port handshake. Auto negotiation supports either topology. Address binding and port selection solve different configuration problems.

--port · --data-port · --single-port

What you need to run it.

Two machines on the same home network: the PC that runs PS2 Servers, and the PS2 that loads your games from it. The PC side is deliberately light — no Python and no heavy runtime for the packaged app.

Your PC

  • OS Windows x64/x86, Linux x64, or macOS Intel/Apple Silicon
  • Packaged No Python needed; the download bundles everything
  • From source Python 3.12 used by CI; Tkinter for GUI (Linux: python3-tk)
  • Hardware Desktop is a small Tkinter app; Edge has ARM/MIPS and other headless targets
  • Network Same LAN as the PS2; wired recommended for big games

Your PS2

  • Console A PS2 that boots homebrew (FreeMcBoot, FreeDVDBoot, modchip…)
  • Loader A homebrew loader with the chosen network protocol
  • Adapter PS2 Ethernet — built into slims, SCPH‑10281 on fat units
  • Emulator PCSX2 with a network adapter works for testing too

Compressed images

  • Packaged Desktop bundles CHD/CSO/ZSO support; check Compression support in the app
  • ZSO From source, add lz4
  • CHD From source, add a libchdr native library
  • CSO Always available — pure Python

UDPFS: virtual .iso. HTTP: CHD/CSO decode on server, ZSO on client. Edge: no CHD.
