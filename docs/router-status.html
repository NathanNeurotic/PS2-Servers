Router & Server Status

PS2 Servers includes a lightweight, broadcast-based status discovery protocol. This allows desktop management tools, monitoring scripts, and client launchers to detect running server instances and query real-time operational telemetry across the local network.

Discovery Protocol Summary
By broadcasting a small probe packet to UDP port 62966, any device on the LAN can identify active Edge routers, active server services (SMB, UDPFS, UDPBD), and current streaming throughput without needing SSH credentials.

1. Protocol Specification

The status discovery protocol operates over raw UDP datagrams:

Field Specification
Port UDP 62966 (or configured status port)
Probe Format Short magic broadcast query
Reply Format JSON / structured telemetry payload containing hostname, version, running subcommands, and active client counts

2. Querying Status from the Terminal

You can query any PS2 Servers instance using a simple Python snippet or netcat:

python -c "
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
s.settimeout(2.0)
s.sendto(b'PS2S_STATUS_PROBE', ('255.255.255.255', 62966))
try:
    data, addr = s.recvfrom(2048)
    print(f'Server reply from {addr}: {data.decode()}')
except socket.timeout:
    print('No server response on LAN')
"

3. Edge Status Configuration

In Edge, status replies are enabled by default on the discovery port. If multiple processes share a machine, or if you wish to disable telemetry replies, use the following options:

  • --status-port -1 — Default: uses primary UDPFS port 62966.
  • --status-port 0 — Completely disables status discovery replies on this process.
  • --status-port PORT — Binds status replies to a dedicated custom UDP port.
