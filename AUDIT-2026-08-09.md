## A. High — ship-blocking or user-visible breakage

### A1. The Edge router binary more than doubled in size (3.31 MB → 7.19 MB)

**Location:** `native/ps2servers-edge/internal/webui/` (introduced by #166/#167),
`.github/workflows/edge-build.yml`

**Measured, same flags (`-trimpath -ldflags="-s -w"`, `GOOS=linux GOARCH=mipsle`):**

| commit | size |
|---|---|
| `e5eb3d4` (before the Web GUI) | **3.31 MB** (3,473,601 B) |
| `71a87db` (`HEAD`) | **7.19 MB** (7,536,833 B) |

+3.88 MB, +117%, in one feature. `3.31 MB` is exactly the figure recorded in
`PICKUP-FROM-HERE.md`, so this is a clean before/after.

**Why it's bad.** The whole point of #143 was fitting Edge onto 32 MB routers,
and the mipsle build is the single binary all three of FatBaldDad's EtherDrive
boards take. Budget router flash partitions in this class are commonly 8 MB or
16 MB total; a 7.19 MB binary is a plausible "cannot install" on the small end
and a large chunk of the rest. The cost is `net/http` + `encoding/json` +
`embed`ded HTML/CSS/JS, and **every** target pays it — including boards that
will never run `webui`.

**Fix.** Put the web UI behind a build tag (e.g. `//go:build webui`), build the
router targets without it, and keep it on for `linux-amd64`/`arm64`/windows
where size does not matter. If the GUI must stay in every build, at minimum add
a hard size gate to `edge-build.yml` so the next regression fails CI instead of
shipping.

**Why that fixes it.** The linker only pulls in `net/http` if something
references it; excluding the package from the router builds returns them to the
~3.3 MB they were validated at. A CI size budget turns "nobody measured" into a
red build.

### A2. The Web GUI dashboard can never show a service as running

**Location:** `native/ps2servers-edge/internal/webui/service.go:172-179`

```go
nameLen := int(buf[18])
if n >= 19+nameLen && nameLen > 0 {
    nameStr := strings.ToLower(string(buf[19 : 19+nameLen]))
    if !strings.Contains(nameStr, strings.ToLower(targetService)) {
        return unknown        // <-- always taken
    }
}
```

**Reproduced.** With Edge `udpfs` genuinely serving on 62966, `GET /api/status`
returned:

```json
{"smb":{"running":false,"state":"unknown",...},
 "udpbd":{"running":false,"state":"unknown",...},
 "udpfs":{"running":false,"state":"unknown",...}}
```

A raw UDP status query to the same port at the same moment returned a perfectly
valid reply: `state=1 (ready)`, `flags=0x11`, `uptime=16`, `name="PS2 Servers Edge"`.

**Why it's bad.** All three servers set `Name: "PS2 Servers Edge"`
(`internal/udpfs/status.go:24`, `internal/smb/server.go:218`,
`internal/udpbd/server.go:204`). The substring test looks for `"udpfs"` /
`"smb"` / `"udpbd"` inside `"ps2 servers edge"`, which never matches, so every
service reports `unknown`. The headline feature of the new GUI — the status
dashboard — is non-functional in every configuration.

**Fix.** Discriminate on the **service flags**, which exist for exactly this and
are already populated: `protocol.FlagServesUDPFS` (bit 0),
`FlagServesUDPBD` (bit 1), `FlagServesSMB` (bit 2), at `buf[10:12]`.

**Why that fixes it.** The flags are a per-service capability bitmap set by each
server; the name is a human display string that was never meant to be parsed.

### A3. Even with A2 fixed, the dashboard reads the wrong JSON key

**Location:** `native/ps2servers-edge/internal/webui/assets/app.js:94` vs
`internal/webui/service.go:27`

The Go struct emits `"state"`; the frontend reads `s.status`:

```js
updateStatusBadge(`dash-${svc}-status`, s.status || 'unknown');
```

`s.status` is always `undefined`, so the badge falls back to `'unknown'`
unconditionally. This is a **second, independent** cause of the same symptom —
fixing A2 alone leaves the dashboard grey.

**Fix.** `s.state`. **Why:** it matches the `json:"state"` tag that the server
actually serialises.

### A4. The Web GUI is an unauthenticated remote-management API on `0.0.0.0`

**Location:** `native/ps2servers-edge/internal/webui/api.go` (all handlers),
`webui.go:77-101`, default bind `0.0.0.0:8082`

**Reproduced against a live instance, with no credentials of any kind:**

| Request | Result |
|---|---|
| `GET /api/browse?path=C:/Windows` | full directory listing with names and sizes |
| `GET /api/config` | complete server configuration |
| `POST /api/config` | accepted, config rewritten |
| `POST /api/restart -d '{"service":"all"}'` | `{"ok":true}` |

There is no auth mechanism at all — not disabled, **absent**. `--no-browse`
only removes `/api/browse`; config write and restart stay open.

Four distinct problems stack here:

1. **No authentication.** Any host on the LAN — or any device on a guest
   Wi-Fi that can reach the router — reconfigures and restarts the servers.
2. **No CSRF defence.** The POST handlers use `json.NewDecoder(r.Body)` and
   never check `Content-Type` or `Origin`, so an ordinary cross-origin form
   post from any page the operator visits reaches them. Combined with (1),
   a drive-by page reconfigures the router.
3. **Arbitrary-path directory disclosure.** `HandleBrowse` accepts any absolute
   path (`api.go:187`); the `strings.Contains(path, "..")` test is decorative
   next to that. `/etc`, `/root`, `/tmp` are all enumerable.
4. **Stored XSS.** `app.js:383` interpolates a filename straight into
   `innerHTML`:
   ```js
   div.innerHTML = `<span…>${icon}</span><span>${item.name}</span>${sizeStr}`;
   ```
   A file named `<img src=x onerror=…>` on the served disk — trivially planted
   if UDPFS or SMB is writable, which is how people copy games on — executes in
   the operator's browser and can drive every endpoint above. `app.js:400` puts
   a server-controlled error string into `innerHTML` the same way.

**Why it's bad.** `docs/EDGE.md:241` says the dashboard is "unauthenticated **by
default**", which implies a non-default that does not exist, and the OpenWrt UCI
comment buries the caveat where nobody reads it. Meanwhile `docs/OPENWRT.md:178`
actively instructs users to open it: "Open `http://<router-ip>:8082` in any
browser". Every other network surface in this project got auth attention — SMB2
has NTLMv2, SMBv1 got optional credentials — and this one skipped it.

**Fix, in priority order.**
1. Default `--bind` to `127.0.0.1`, requiring an explicit `--bind 0.0.0.0` to
   expose it. Also flip the OpenWrt/systemd samples.
2. Add HTTP Basic (or a token) with a first-run generated password printed to
   the log; refuse to bind a non-loopback address without one.
3. Require `Content-Type: application/json` **and** an `Origin`/`Sec-Fetch-Site`
   check on every mutating handler.
4. Confine `/api/browse` to the configured roots (the share paths), not `/`.
5. Replace `innerHTML` with `textContent` + `createElement` at `app.js:383` and
   `app.js:400`.

**Why those fix it.** (1) and (2) close the "anyone on the LAN" hole. (3) closes
the "any web page the admin opens" hole, which auth alone does not. (4) and (5)
remove the two paths that let untrusted *data* — path names and file names —
reach a privileged context.

### A5. Remote UCI command injection through `POST /api/config` (OpenWrt)

**Location:** `native/ps2servers-edge/internal/webui/config_uci.go:145-225`

```go
cmds = append(cmds, []string{"set", fmt.Sprintf("ps2servers-edge.%s=%s", key, sval)})
…
for _, c := range cmds { buf.WriteString(strings.Join(c, " ") + "\n") }
cmd := exec.Command("/sbin/uci", "batch"); cmd.Stdin = &buf
```

`uci batch` reads **one command per line**. Every string field
(`root`, `share`, `image`, `bind`, `peer_timeout`, `log_format`, …) is written
into that stream unescaped and unvalidated, straight from the unauthenticated
JSON body of A4.

- A value containing `\n` injects arbitrary `uci` commands — any package's
  config, not just this one (`set firewall.…`, `set dropbear.…`, `commit …`).
- A value containing a space silently changes how the line parses, so an
  ordinary user whose games live in `/mnt/My Games` gets a corrupted config with
  no error.

**Why it's bad.** This is remote configuration write on a router, reachable by
any LAN host, with no credential. `start_webui` in the init script even
`chown`s `/etc/config/ps2servers-edge` to the service user specifically to let
this path write (see A9).

**Fix.** Reject any value containing a newline or control character before
building the batch (return 400). Better: drop `uci batch` and call
`uci set <key> <value>` per option with the value as a **separate argv element**,
which never goes through line-splitting; then one `uci commit ps2servers-edge`.
Validate enums (`protocol`, `log_format`) against their allowed sets and clamp
ports to 1–65535.

**Why that fixes it.** Passing the value as its own argv element removes the
text channel entirely — there is no line for a newline to break out of. The
enum/range validation stops the remaining garbage-in cases that merely produce a
server that will not start.

FAIL: test_main_go_dispatches_the_expected_set
AssertionError: Items in the first set but not the second:

The guard-on-the-guard still hardcodes `{"udpfs", "udpbd", "smb"}`. The

### A7. The systemd UDPBD unit ships the wrong port — the service is unreachable

**Location:** `packaging/systemd/ps2servers-edge-udpbd.env:11`,
`packaging/openwrt/files/ps2servers-edge.init:153`

```
PS2EDGE_ARGS=--image /srv/ps2/ps2.img --port 48301 --status-port 0
                                             ^^^^^
config_get port udpbd port 48301
                           ^^^^^
```

The UDPBD port is **not configurable from the console side**. It is `0xBDBD` =
**48573**, fixed: `udpbd_server/udpbd_server.py:27` — "*fixed; the PS2
broadcasts here to find us*". Everything else in the tree agrees on 48573 —
`internal/udpbd/protocol.go:24`, `internal/webui/config.go:97`,
`packaging/openwrt/files/ps2servers-edge.config:53`, both `INSTRUCTIONS.md`.
Only these two packaging files say 48301.

**Why it's bad.** A user who follows `packaging/systemd/README.md` gets a UDPBD
server bound to a port no PS2 will ever send to. The console broadcasts, nothing
answers, and there is no error on either side — the exact "silence" failure mode
already recorded for UDPBD. The OpenWrt case is narrower (only bites if the
`port` option is absent, e.g. a section the Web GUI created), but it is the same
wrong number.

**Fix.** 48573 in both places. Then extend
`tests/test_systemd_units.py::EnvFileFlagsAreReal` — which today checks only
that flag *names* exist, and only for the Python `ps2servers-*.env` files — to
also cover `ps2servers-edge-*.env` and to compare each **value** against the
binary's own default.

**Why that fixes it.** The literal is the bug; the test extension is what stops
the next one, since the current test would have passed this file unchanged.

## B. High — process

### B1. CI runs 1 of 26 test modules on a pull request

**Location:** `.github/workflows/ci.yml:35`

```yaml
- name: Check the packaged build ships every server source
  run: python -m unittest tests.test_packaging_data_files -v
```

That is the only `tests/` invocation in `ci.yml`. `edge.yml` adds two more
(`test_udpfs_protocol_negotiation`, `test_udpfs_config`) and only on paths that
touch Edge. **23 of 26 modules — roughly 450 tests — gate nothing.**

That is why A6 is sitting red on `main`, and why nothing noticed. It also means
`test_directlink` (87 tests), `test_smb2_server` (44), `test_udpfs_config` on
non-Edge PRs, `test_gui_layout`, `test_smb_wire_parity` and the rest are, in
CI's eyes, decoration.

The suite itself is genuinely good — the comments in `test_edge_service_modes.py`
and `test_smb_wire_parity.py` show tests written against real past incidents.
That work is being thrown away by the workflow.

**Fix.** Replace the single invocation with discovery over the whole directory:

```yaml
- name: Python tests
  run: python -m unittest discover -s tests -t . -v
```

(Discovery needs `tests/__init__.py`, which does not currently exist — that or
`-p 'test_*.py'` with the repo root on `PYTHONPATH`.)

**Why that fixes it.** One line makes every existing test load-bearing. Add the
Go side too: `edge.yml` runs `go vet` but never `gofmt -l`, which is why C3 got in.

### B2. `tests/test_smb_wire_parity.py` fails silently-ish and skips silently

**Location:** `tests/test_smb_wire_parity.py:80-83, 91, 114, 148`

Two problems, one observed:

- **Observed once**: on the first run in this session all three tests failed with
  `AssertionError: 0 != 4` / `0 != 3` / `0 != 22` — `go run` exited 0 and
  produced no stdout. It has not reproduced since (I re-ran it four times, and
  tried a cold `GOCACHE`, all green), so I cannot name the cause. What matters
  is the diagnostic: `0 != 4` tells a maintainer nothing, and the captured
  stdout/stderr are discarded on the success path.
- `setUp` calls `self.skipTest("no Go toolchain on PATH")`. Combined with B1,
  a real Go/Python wire divergence would be reported as a skip nobody sees.

**Fix.** Assert on emptiness explicitly with the process output in the message —
`self.assertTrue(lines, "go run produced no output:\n" + result.stdout + result.stderr)` —
and keep `result.stdout`/`stderr` on the object for the failure message. Make CI
fail rather than skip when Go is absent, since the Edge workflow always has Go.

**Why that fixes it.** It converts a mystery into a report; the skip change stops
the test from being a no-op in the one place it is supposed to run.

## C. Medium — real defects, lower blast radius

### C1. The Web GUI "Logs" tab can never show a line

**Location:** `native/ps2servers-edge/internal/webui/logbuffer.go`,
`cmd/ps2servers-edge/main.go:427-438`

```go
logger := edgelog.New(os.Stdout, *logFormat, *quiet, *verbose)   // writes to stdout
logBuffer := webui.NewLogBuffer(*logLines)                       // written to by nobody
```

`LogBuffer.Write` — the `io.Writer` the whole type exists to be — is never
called anywhere outside `webui_test.go`. `/api/logs` streams an empty buffer and
then blocks forever. `docs/OPENWRT.md:178` advertises the feature ("tail live
logs") regardless.

There is a second, structural half: `webui` is a **separate process** from
`udpfs`/`smb`/`udpbd` under both procd and systemd, so even once wired it would
only ever show its own logs, not the servers'.

**Fix.** Short term: `edgelog.New(io.MultiWriter(os.Stdout, logBuffer), …)` so
the tab shows *something* truthful. Real fix: read the service logs from where
they actually go — `logread` on OpenWrt, `journalctl -u ps2servers-edge@*` on
systemd — behind the same `ServiceManager` abstraction that already
auto-detects the platform. Until then, stop advertising it in the docs.

**Why that fixes it.** The `MultiWriter` connects the type to a producer; the
`logread`/`journalctl` version connects the endpoint to the logs a user cares
about, which are in another process.

### C2. Restart is wrong on OpenWrt and unvalidated on systemd

**Location:** `native/ps2servers-edge/internal/webui/service.go:50-77`

```go
func (m *openwrtManager) Restart(service string) error {   // `service` unused
    return exec.Command("/etc/init.d/ps2servers-edge", "restart").Run()
}
…
return exec.Command("systemctl", "restart", "ps2servers-edge@"+service).Run()
```

- **OpenWrt:** the parameter is ignored. Clicking "restart SMB" restarts udpfs
  and udpbd too, dropping any console session mid-transfer, with the UI
  reporting a clean per-service restart.
- **systemd:** `service` is concatenated with no allowlist. There is no shell, so
  this is not shell injection, but an unauthenticated caller (A4) chooses which
  `ps2servers-edge@<anything>` instance systemd starts — and the instance name
  becomes `%i`, which the unit passes as the binary's subcommand argument.

**Fix.** Validate `service` against `{"udpfs","smb","udpbd","all"}` in
`HandleRestart` before it reaches any manager. On OpenWrt use
`/etc/init.d/ps2servers-edge restart` only for `"all"`, and per-service use
procd's instance control (`ubus call service …`) or document honestly that the
platform restarts everything.

**Why that fixes it.** The allowlist removes the attacker's choice of unit; the
OpenWrt change makes the button do what the label says, or say what it does.

### C3. The Web GUI needs privileges the init script denies it

**Location:** `packaging/openwrt/files/ps2servers-edge.init:177-193`

```sh
[ -f /etc/config/ps2servers-edge ] && chown ps2edge:ps2edge /etc/config/ps2servers-edge 2>/dev/null
…
common_params        # procd_set_param user ps2edge
```

The `webui` instance runs as `ps2edge`, but the two things it exists to do need
root: `/etc/init.d/ps2servers-edge restart` (C2) and `uci commit`. The `chown`
is a workaround for the second — and an incomplete one, because `uci commit`
writes a temp file in `/etc/config/` and renames it, which needs **directory**
write permission that this does not grant. Errors are swallowed (`2>/dev/null`,
and `uciBackend.Save` surfaces only `exit status 1`), so Save most likely fails
with an unhelpful toast.

Separately, handing an unprivileged, network-reachable service ownership of a
file in `/etc/config` weakens the hardening `common_params` is there to provide,
and it is the file A5 injects into.

**Fix.** Decide the privilege model deliberately. Either (a) keep `webui`
unprivileged and give it a narrow, audited helper — a tiny setuid shim or a
`ubus` method — for exactly "commit this config" and "restart this instance", or
(b) document that management requires root and run only that instance as root
with the rest still confined. Drop the blanket `chown` either way, and surface
`uci`'s stderr in the API error.

**Why that fixes it.** Today the feature is both under-privileged (it silently
fails) and over-privileged (it owns a config file it can be tricked into
rewriting). Splitting the two named operations out gives it exactly what it
needs and nothing else.

### C4. `tests/test_smb2_server.py:719` is a syntax error on Python 3.14

```python
self.assertNotEqual(self._rename(c, fid, "..\escaped.iso", replace=True), 0)
```

`\e` is not a valid escape. On 3.12 it is a `SyntaxWarning`; on 3.14 under
`-W error` it is:

```
SyntaxError: "\e" is an invalid escape sequence. Did you mean "\\e"?
```

The test still passes today because Python leaves the backslash in place, which
happens to be what the test wants.

**Fix.** `r"..\escaped.iso"`.
**Why:** a raw string expresses the intent (a literal Windows-style traversal)
and stops the file from becoming unparseable on a future interpreter. All
non-test sources compile clean on 3.14 — this is the only offender.

### C5. Python UDPFS has none of the transfer caps Edge has

**Location:** `udpfs_server/udpfs_server.py:1522-1532` (READ), `1892-1922`
(BREAD), `1582-1609` (write assembly)

```python
_, _, _, _, handle, size = struct.unpack('<BBBBiI', payload[:12])
…
data = fh.obj.read(size)        # size is an unbounded uint32
```

Edge refuses the same request:

```go
size := binary.LittleEndian.Uint32(p[8:12])
if size > 64<<10 { …EINVAL… }                     // operations.go:322
```

and bounds BREAD and assembled writes against `Server.transferCap`
(`internal/udpfs/blockdev.go:145,197`, `operations.go:374,432`). The Python side
has no equivalent anywhere: a 12-byte datagram asking for `0xFFFFFFFF` bytes is
a 4 GiB allocation attempt, and `BREAD` with `sector_count=65535` is a 33 MB
allocation per packet.

**Why it's bad.** Two implementations speak the same wire protocol and this
project already treats divergence between them as a bug worth a dedicated test
(`test_smb_wire_parity.py` does exactly that for SMB). Here the divergence is
the one that matters for robustness, the Python server is the one that is
hardware-validated and the one the launcher runs, and no test compares limits.

**Fix.** Mirror Edge's numbers in `udpfs_server.py`: reject `READ` over 64 KiB
with `-EINVAL`, and add a `--max-transfer-bytes`-equivalent cap applied to
`BREAD` total size and to the accumulated `write_data` buffer. Then add a
parity test in the shape of `test_smb_wire_parity.py` that asserts both
implementations refuse the same over-limit request.

**Why that fixes it.** Bounding the allocation at parse time is the only place
it can be bounded — once `read(size)` is called the memory is already
requested. The parity test is what keeps the two servers' limits from drifting
again.

### C6. No cap on UDPFS sessions; one datagram costs up to two OS threads

**Location:** `udpfs_server/ps2servers_core.py:243, 278, 295`,
`udpfs_server/udpfs_server.py:690-698`

`_handle_discovery` calls `_get_or_create_session(addr)` (thread #1) and, in
`auto` mode, `_schedule_fallback` starts a second thread that sleeps
`fallback_interval` (thread #2). `_route_data_via` creates sessions the same
way. Nothing is authenticated and nothing is rate-limited, and a session lives
for `--peer-timeout` — **one hour by default**.

The code already knows: `udpfs_server.py:231` says "*without it, every console
reboot strands a session (thread + queue + handles) until the server exits*".
The timeout addresses one stranded session; nothing addresses many.

**Why it's bad.** Sessions are keyed on `(ip, port)`, so a single host walking
source ports creates unbounded sessions. On a PC this is a hang; on a 32 MB
router running the Python server it is an OOM. It is LAN-only, which is why this
is Medium and not High.

**Fix.** Cap concurrent sessions (a few hundred is far above any real console
count), evict least-recently-used past the cap, and log once when the cap is
hit. Optionally require a DISCOVERY before a peer can create a session via DATA.

**Why that fixes it.** A bounded table converts an unbounded resource commitment
into a bounded one, and LRU eviction means a real console displacing a stale
entry still works.

### C7. SMBv1 path containment is lexical, not real — known, documented, unfixed

**Location:** `smbv1_server/smbserver_opl.py:189-197`

```python
full = os.path.abspath(os.path.join(self.root, p))
if full == self.root or full.startswith(self.root + os.sep):
```

`smb2_server/smb2_paths.py:7-26` already documents this exact weakness, names
the file, and gives a worked example of a symlink inside the share resolving to
a path outside it — and concludes "*the newer servers should not inherit the
weaker rule*". `internal/smb/handlers.go:60-61` says the same. The newer servers
were fixed. The old one, which is the SMB server most OPL users actually run,
was not.

Every other resolver in the tree is real-path based: UDPFS
(`udpfs_server.py:908`, `os.path.realpath`), SMB2
(`smb2_paths.py:153` + `os.path.commonpath`), Edge (`internal/filesystem`).

**Why it's bad.** Not remotely exploitable on its own — SMBv1 here implements no
command that creates a symlink — but the declared share root is not the actual
boundary, and symlinking a games folder onto a second disk is a normal thing for
users to do. The rule differs between three servers that are presented as
interchangeable.

**Fix.** Use `smb2_server.smb2_paths.RootedPath` from `smbserver_opl.py` rather
than duplicating a third resolver.

**Why that fixes it.** It is already written, already tested
(`tests/test_smb2_paths.py`, 19 tests), and makes the three servers agree.

### C8. The Web GUI hand-rolls a protocol the module already implements

**Location:** `native/ps2servers-edge/internal/webui/service.go:105-205`

`queryStatus` open-codes the router status query and reply: it rebuilds the
10-byte packet with literal `0xF5F7` and `"PS2S"`, and decodes the reply with
hardcoded offsets `buf[9]`, `buf[12:14]`, `buf[14:18]`, `buf[18]`, plus its own
copy of the state-code switch.

`internal/protocol/status.go` — in the same module — already provides
`MarshalStatusQuery()`, `ParseStatusReply()` and `ServerState.String()`, with
validation the copy omits (version byte check, unknown-state-degrades-not-
unknown). The duplicate has **already drifted**: it ignores the `Flags` field
entirely, which is what caused A2.

**Fix.** Delete the hand-rolled codec and call the protocol package.

**Why that fixes it.** A2 disappears as a side effect — `ParseStatusReply`
returns `Flags`, which is the correct discriminator — and the next protocol
revision updates one implementation instead of two.

### C9. `uciBackend.Load` turns any failure into "here are the defaults"

**Location:** `native/ps2servers-edge/internal/webui/config_uci.go:16-20`

```go
out, err := exec.Command("/sbin/uci", "show", "ps2servers-edge").Output()
if err != nil {
    // If the config doesn't exist yet, return defaults
    return cfg, nil
}
```

The comment covers one cause; the code covers all of them — `uci` missing,
permission denied, a corrupt config. The GUI then displays defaults as if they
were the live config, and the operator clicking **Save** writes those defaults
over a working configuration. Combined with C3 (`ps2edge` may not be able to
read/write the file), permission-denied is a realistic trigger.

**Fix.** Distinguish "section not found" (uci exit 1 with empty output) from
every other failure, and return the error for the latter so the UI shows it.

**Why that fixes it.** It stops a read failure from silently becoming a
destructive write.

### C10. `DetectBackend` ignores the config path you explicitly passed

**Location:** `native/ps2servers-edge/internal/webui/config.go:118-129`

```go
if jsonPath != "" && jsonPath != defaultJSONConfigPath { return &jsonBackend{…} }
if _, err := os.Stat("/sbin/uci"); err == nil { return &uciBackend{} }
```

Passing `--config-file /etc/ps2servers-edge/config.json` — which is exactly what
`packaging/systemd/ps2servers-edge-webui.env:4` ships — is treated as "no
preference", so on any box that also has `/sbin/uci` the explicit flag is
silently discarded and UCI wins.

**Fix.** Track whether the flag was set (`flag.Visit`, or a sentinel default of
`""`) instead of comparing the value against the default.

**Why that fixes it.** "The user named the default path" and "the user named
nothing" are different intents; only the flag's set-ness distinguishes them.

### C11. SSE log subscribers are unbounded and are dropped without a word

**Location:** `native/ps2servers-edge/internal/webui/logbuffer.go:46-53`,
`api.go:144`

`Subscribe()` has no cap — with no auth (A4), N connections is N goroutines and
N × 100-string channels on a 32 MB router. And a subscriber that falls one
buffer behind is deleted and its channel closed, which ends the client's stream
with no message; the frontend just reconnects and starts over.

**Fix.** Cap concurrent subscribers (reject with 503 past it) and, before
dropping a slow one, push a `data: [log stream fell behind, reconnecting]`
line so the gap is visible.

**Why that fixes it.** The cap bounds the cost; the marker turns a silent hole
in the log into a stated one.
