### PS2SERVERS-011 — WEAKENED
The defect is real but materially narrower than stated. The finding claims the SESSION counting/format is "implemented three times, plus a private stats dict inside every server," with per-server private counters in five servers. Re-reading each named site shows the opposite architecture in Python: every named per-server function is a 3–4-line adapter that delegates to the one shared implementation — `smb2_server.py:380-384` `_session_record` → `self.session_stats.record(conn.peer[0], kind, count)`; `udpbd_server.py:188-192` `_record` → `stats.record(addr[0], kind, count)`; `http_server.py:852-855` `_stat` → `self.server.stats.record(...)`; `udpfs_server.py:639-643` `_session_record` → `stats.record(addr[0], kind, count)`. There is no private dict "inside every server": in UDPBD and HTTP the attribute named `stats` **is** the shared `SessionStats` object passed in (`udpbd_server.py:148` `self.stats = stats`; `http_server.py:1104` `self.stats = stats`). Only UDPFS has a genuinely private dict (`udpfs_server.py:815` `self.stats = {…}`), and the code explicitly separates it from the SESSION contract: "Separate from self.stats, the server-wide totals printed at shutdown" (`udpfs_server.py:634-637`) — a different output (shutdown totals), not a third SESSION implementation. The NFS citation does not support the claim at all: `grep -n "SessionStats\|session_stats" nfs4_server/nfs4_server.py` returns nothing, and the cited `_admit`/`_serve` are the connection accept/serve loop (`nfs4_server.py:412-413`), not counting code — NFS simply does not participate in session stats. **Narrowed claim that survives:** the SESSION line format/contract is implemented exactly twice, once per language (Python `launcher/session_stats.py`, 131 lines, `SessionStats` :36 and `parse_line` :120; Go `internal/sessionstats/sessionstats.go`, 266 lines including its own `Parse` at :247), plus ~4-line `record` adapters per Python server, UDPFS's separate shutdown-totals dict, and NFS not reporting at all. The estimated "−150 lines" from deleting private dicts is not supported by what is actually in the tree.
